## 2. Content migration

`scripts/migrate-jekyll.mjs` reads every post from the `legacy-jekyll` branch. If that branch is
missing, it uses the source commit recorded in `migration/inventory.json`. For each post it:

1. keeps the original front matter **text** verbatim and appends `date` (from the file name, UTC as on
   GitHub Pages), `legacyPath`, `legacySource`;
2. keeps the body byte-for-byte unless a rule below applies;
3. writes `migration/inventory.json` with source/target paths, URLs, metadata, SHA-256 of the source and
   migrated bodies, and every transformation with its line number.

`npm run migrate -- --check` regenerates in memory and fails on any difference. `npm run verify`
re-derives the comparison from Git.

### Transformations (17 of 70 posts touched; all others byte-identical)

| Rule | Count | Why |
| --- | --- | --- |
| `liquid-variable` | 2 | `{{ page.title }}`, `{{ page.last_modified_at }}` replaced by the exact strings Jekyll rendered (`2023-03-30 08:06:00 -0500`) |
| `liquid-highlight` | 1 | `{% highlight jsp linenos %}` → fenced ```` ```jsp linenos ```` (line numbers kept) |
| `html-inline-line` (R1) | 37 | a line holding only `<br>`/`<img>` opens a CommonMark HTML block that swallowed the following Markdown (images, lists, code spans showed as raw text) |
| `blockquote-lazy` (R5) | 25 | kramdown continues a `>` quote over following lines until a blank line (lists, fences, gists inside the quote) |
| `script-trailing` (R2) | 3 | Markdown after `<script…></script>` on the same line stayed raw |
| `ordered-list-break` (R4) | 3 | `2. …` directly after a paragraph is a list in kramdown, plain text in CommonMark |
| `unclosed-script` (R3) | 1 | a gist `<script src>` without `</script>`; raw passthrough would hide the rest of the page |
| `autolink-scheme` (R6) | 5 | `<jsp:include>` in prose: hidden HTML tag in kramdown, a broken `jsp:` link in CommonMark → shown as literal text |

### Rendering comparison against the live site

All 70 live articles were fetched and their rendered text, images and links compared with the Astro
output. Results after migration:

- text identical (ignoring whitespace): 65/70; images identical: 70/70; links identical: 69/70;
- remaining differences are intentional or typographic:
  - `<jsp:include>` is now visible in headings of 웹서버개발10. The live site hid it, which also changes
    those two heading anchors.
  - In 로그인인증방식, a code fence that kramdown failed to recognize (it showed literal ```` ``` ````) now
    renders as a code block.
  - Smart-quote direction differs in a few places (‘ vs ’).
  - A table cell `` ` ` `` is now an empty code span.
  - 웹서버개발2 gains a bare-URL autolink (GFM).
- list grouping differs in some posts (CommonMark keeps source numbering such as `2.`, `3.` where kramdown restarted lists).

### Rendering policy

Raw HTML inside posts is trusted author content and is passed through as authored (gist scripts,
`<details>`, mermaid images, `<br>`). Values from users (search queries, lab input) and from remote
sources (Pagefind excerpts) are never inserted as HTML: text is set with `textContent`, and search
highlights are rebuilt as `<mark>` elements.

## 3. URL compatibility

- `legacyPath` is computed once from the **original** categories and file name and stored in each post.
  Normalized taxonomy (for example `Ubuntu` and `ubuntu` merged in the Knowledge Modules) never affects
  URLs.
- New posts without `legacyPath` get the same Jekyll rule at build time.
- Build-time guards reject duplicate paths and collisions with site routes (`/posts/`, `/page2/`, …).
- Trailing slashes: `trailingSlash: 'always'`, `build.format: 'directory'`. On GitHub Pages
  `/path` redirects to `/path/` exactly as before.
- Old archive anchors are kept: `/categories/#<slug>` and `/tags/#<slug>` (lowercase slug, as Minimal
  Mistakes generated them).

## 4. Deployment (current state)

Deployed on 2026-11-24 from `main` (commit `a4d87f3`, a fast-forward of the former `astro-arc-lab`
branch, which has since been deleted).

- **Settings → Pages → Source:** GitHub Actions.
- **Repository variable** `PAGES_DEPLOY_ENABLED = true` (Settings → Secrets and variables → Actions →
  Variables). The `deploy` job runs only when it is `true`; a secret or an environment-level variable
  of the same name is not read.
- **Workflow** `.github/workflows/deploy.yml`: on pushes to `main` it installs, type-checks, builds,
  runs `npm run verify` and deploys. Pull requests and manual runs (`workflow_dispatch`) build and
  verify; manual runs on `main` also deploy.
- **Branches:** `main` (Astro site) and `legacy-jekyll` (`f83aa10`, last Jekyll state, kept for rollback).

Publishing a post: add the Markdown file under `src/content/posts/`, push to `main`, and the site
deploys automatically. Smoke test after larger changes: `/`, `/linux/ubuntu/LXD_설치및사용/`,
`/FileUpload실습(2)/`, `/page14/`, `/feed.xml`, comments on `/안녕하세요/` (existing thread),
Ctrl+K search for `취약점`.

## 5. Rollback

- **Fast:** Settings → Pages → Source: *Deploy from a branch* → `legacy-jekyll` / `(root)`. GitHub Pages
  rebuilds the untouched Jekyll site (requires `legacy-jekyll` to be pushed). Optionally also set
  `PAGES_DEPLOY_ENABLED` to `false`.
- **Permanent:** on `main`, `git revert a4d87f3` (the migration commit; the merge was a fast-forward,
  so there is no merge commit) — no history rewrite — then switch the Pages source back to
  *Deploy from a branch: main*.
- Comments are unaffected either way: utterances threads are keyed by URL pathname, and both sites use
  the same pathnames.
